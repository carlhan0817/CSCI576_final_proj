# Phase 4.5 — Player Design

## 1. Goal

Deliver the deliverable described in PDD §4.5: a single-process FastAPI app that
serves the analyzed videos plus a minimal HTML/JS player. The player must
satisfy the course rubric:

> "A player that can represent segmented temporal segments of the video along
> with navigation capabilities — play, stop, skip to next segment, with an
> interactive timeline."

…and the PDD §4.5 add-on requirement of a human-verification edit mode that
writes back to disk.

Visual polish is explicitly **out of scope** ("most basic web to test the
program and pass the exam"). Functional correctness and demo-day reliability
are the only quality bars.

## 2. Non-Goals

- No build tooling (no npm, no bundler, no framework).
- No CSS framework, no D3, no Vue. Plain HTML + vanilla JS + minimal CSS.
- No authentication, no multi-user, no concurrency control on POST.
- No partial-update PATCH endpoint — the POST replaces the entire metadata
  document.
- No frontend tests. Only backend tests.
- No CORS handling — the same FastAPI app serves both API and static frontend.
- No changes to anything in `backend/pipeline/`. Phase 4.4 (export.py) is the
  teammate's scope; this phase consumes its output and never modifies it.

## 3. Architecture

### 3.1 Approach chosen

**Single FastAPI process serving JSON API + MP4 + static frontend.** Pick a
video → its `metadata.json` is fetched once → the page renders timeline +
table → human edits flow back through one POST.

Rejected alternatives (one line each):
- *API-only backend + frontend opened from `file://`*: needs CORS, two URLs,
  no upside for a demo.
- *Patch-style POST endpoint*: more endpoint surface, no benefit when the
  whole document fits in one request.

### 3.2 Process layout

```
uvicorn backend.server.app:app  →  http://localhost:8000
  ├─ /                 → index.html              (static)
  ├─ /static/*         → frontend/static/*       (css, js)
  ├─ /api/videos       → JSON list               (api)
  ├─ /api/metadata/{id}→ JSON read / write       (api)
  └─ /videos/<id>.mp4  → mp4 with HTTP Range     (static)
```

### 3.3 Directory layout (new files only)

```
Final_proj/
├── backend/
│   └── server/
│       ├── __init__.py
│       ├── app.py            # FastAPI app factory + route mounts
│       ├── config.py         # Resolves workspace_root and videos_root from env or defaults
│       └── routes.py         # The three /api endpoints
├── frontend/
│   ├── index.html
│   └── static/
│       ├── player.js
│       └── player.css        # Tiny — color-per-label only
├── videos/                   # User drops MP4s here. .gitkeep committed.
└── tests/
    └── test_server.py        # Happy + sad paths via FastAPI TestClient
```

Add `fastapi` and `uvicorn` to `pyproject.toml` `[project] dependencies`,
plus `httpx` to the `dev` extra (TestClient transitive dep is already
declared on httpx in modern fastapi, but pinning it explicitly avoids
surprise during the demo).

## 4. Backend — `backend/server/`

### 4.1 `config.py`

A frozen dataclass `ServerConfig` resolves three paths once at startup:

| Field            | Default                                         | Override env var |
|------------------|-------------------------------------------------|------------------|
| `workspace_root` | `<repo>/workspace`                              | `MM_WORKSPACE`   |
| `videos_root`    | `<repo>/videos`                                 | `MM_VIDEOS`      |
| `frontend_root`  | `<repo>/frontend`                               | `MM_FRONTEND`    |

`app.py` instantiates one `ServerConfig` and stuffs it into
`app.state.config` so routes and tests can override per-call via dependency
injection.

### 4.2 `app.py` — wiring

```python
def create_app(config: ServerConfig | None = None) -> FastAPI:
    config = config or ServerConfig.from_env()
    app = FastAPI(title="Multimedia Segmentation Player")
    app.state.config = config
    app.include_router(routes.router)
    app.mount("/videos", StaticFiles(directory=config.videos_root), name="videos")
    app.mount("/static", StaticFiles(directory=config.frontend_root / "static"), name="static")
    @app.get("/")
    def index(): return FileResponse(config.frontend_root / "index.html")
    return app

app = create_app()
```

The factory pattern lets `test_server.py` inject a `tmp_path`-backed config
without monkey-patching globals.

### 4.3 `routes.py` — endpoints

#### `GET /api/videos → 200 list[VideoSummary]`

A "video" is a `(stem, mp4_path, metadata_path)` triple where **both**
`videos/<stem>.mp4` and `workspace/<stem>/metadata.json` exist (decision Q1
locked to option B). Returns:

```json
[
  {"video_id": "lecture01", "filename": "lecture01.mp4",
   "duration_sec": 3600.0, "verified_by_human": false}
]
```

Implementation: enumerate `videos_root.glob("*.mp4")`, filter to those whose
stem has a `metadata.json`, parse that JSON's `video_info` block. If none,
return `[]` (sad path **a**).

#### `GET /api/metadata/{video_id} → 200 Metadata | 404`

- 404 if `workspace/<video_id>/metadata.json` doesn't exist (sad path **b**).
- Otherwise read, validate via Pydantic `Metadata`, return.

#### `POST /api/metadata/{video_id} → 200 Metadata | 404 | 422`

Body must validate against the `Metadata` schema (decision Q2 locked to
option A — full replacement). Server behavior:

1. 404 if the workspace dir doesn't exist (sad path **e**).
2. FastAPI's request-body validation handles malformed bodies → 422 (sad
   path **d**).
3. Server forces `video_info.verified_by_human = true` regardless of what
   the client sent. (Client cannot un-verify by accident.)
4. Atomic write: serialize → write to `metadata.json.tmp` → `os.replace()`
   onto `metadata.json`. Prevents corrupting the file if the process dies
   mid-write.
5. Return the saved document so the client can refresh state.

#### Static MP4

Mounted via `StaticFiles`. FastAPI/Starlette returns 404 for missing files
(sad path **g**) and supports HTTP `Range` requests natively, which the
browser `<video>` uses for seek. Nothing custom needed.

### 4.4 Error contract summary

| Endpoint                        | Status | When |
|---------------------------------|--------|------|
| `GET /api/videos`               | 200    | Always (empty list if none) |
| `GET /api/metadata/{id}`        | 200    | metadata.json exists & validates |
| `GET /api/metadata/{id}`        | 404    | workspace dir or metadata.json missing |
| `POST /api/metadata/{id}`       | 200    | Body valid, file written |
| `POST /api/metadata/{id}`       | 404    | Workspace dir missing |
| `POST /api/metadata/{id}`       | 422    | Body fails Pydantic validation |
| `GET /videos/{id}.mp4`          | 200/206| File exists (206 for Range) |
| `GET /videos/{id}.mp4`          | 404    | File missing |

## 5. Frontend — `frontend/`

### 5.1 `index.html`

Single page. Layout from top to bottom:

```
[ <select id="video-picker"> ... ]
[ <video id="player" controls></video> ]
[ <div id="timeline">  <!-- N child blocks injected by JS --> ]
[ <button id="next-seg">Next Segment</button>
  <label><input type="checkbox" id="skip-non-content"> Skip non-content</label>
  <button id="save-edits">Save to Server</button> ]
[ <table id="segment-table"> ... </table> ]
```

No semantic markup beyond the above. No header, no footer, no help text.

### 5.2 `player.css`

Defines exactly one rule set: a colour per `data-label` attribute on
timeline blocks (10 colors). Plus `#timeline { display: flex; height: 24px;
border: 1px solid #888; }` and a one-line hover style. Total ≤ 30 lines.

### 5.3 `player.js` — state machine

Single global `state` object:

```js
const state = {
  videoId: null,
  metadata: null,        // the full Metadata document
  durationSec: null,
  skipMode: false,
  dirty: false,          // true if user changed any label
};
```

Functions (all pure or mutating `state`/DOM, no classes, no modules):

| Function                          | Trigger                                  |
|-----------------------------------|------------------------------------------|
| `loadVideoList()`                 | page load                                |
| `loadVideo(videoId)`              | dropdown change                          |
| `renderTimeline()`                | after metadata load and after save       |
| `renderTable()`                   | after metadata load and after edit       |
| `seekTo(sec)`                     | timeline-block click & next-segment      |
| `onTimeUpdate()`                  | `<video> timeupdate` event               |
| `onLabelChange(segId, newLabel)`  | `<select>` change in table               |
| `saveEdits()`                     | "Save" button click                      |

`onTimeUpdate` powers the auto-skip: if `state.skipMode` and the current
`video.currentTime` falls inside a segment whose `label !== "core_content"`,
set `currentTime = segment.end_sec + 0.05`.

"Next Segment" finds the smallest `start_sec > currentTime` and seeks there.

`saveEdits` POSTs the entire `state.metadata` body. On 200, refresh the
local copy from the server response (which now has `verified_by_human: true`
and `user_corrected: true` flags persisted) and re-render. On 422, alert
with the response detail. No retry, no spinner, no toast — alert() is fine.

## 6. Testing — `tests/test_server.py`

Use `fastapi.testclient.TestClient`. A single `pytest` fixture builds a
throw-away workspace tree under `tmp_path` containing one valid
`metadata.json` (built from the existing Pydantic models so it stays in sync
with phase 4.4) and one MP4 stub (an empty file is enough — we don't read
its bytes from the server tests).

### 6.1 Happy paths

- `GET /api/videos` → 200, list contains the seeded video.
- `GET /api/metadata/{id}` → 200, body validates as `Metadata`.
- `POST /api/metadata/{id}` with a valid body that flips one segment's
  label → 200; re-read on disk and assert the new label is persisted and
  `verified_by_human == true`.
- `GET /videos/<id>.mp4` → 200.

### 6.2 Sad paths (the five locked in Q4)

| Test | Endpoint & condition | Expected |
|------|----------------------|----------|
| **a** | `GET /api/videos` against an empty workspace | 200 with `[]` |
| **b** | `GET /api/metadata/does-not-exist` | 404 |
| **d** | `POST /api/metadata/{id}` with body `{"video_info": {}, "segments": "not a list"}` | 422 |
| **e** | `POST /api/metadata/does-not-exist` with a valid body | 404 |
| **g** | `GET /videos/missing.mp4` | 404 |

Total ~9 tests. Run: `pytest tests/test_server.py -v`.

## 7. Manual demo-day verification (not automated)

After implementation, run through this list once on a real analyzed video:

1. `uvicorn backend.server.app:app --reload`, open `http://localhost:8000`.
2. Pick the video. Confirm `<video>` plays and seeks via the native control.
3. Confirm timeline renders one block per segment, colors match the
   palette, hover shows label + time, click jumps the player.
4. Click "Next Segment" mid-video. Confirm it advances by exactly one
   segment.
5. Toggle "Skip non-content", scrub into a non-content segment, confirm
   the player jumps out automatically.
6. Change one label in the table, click "Save to Server". Confirm:
   - Browser DevTools shows `POST 200`.
   - Reload the page; the new label is still there.
   - On disk, `metadata.json` has `verified_by_human: true` and the
     edited segment has `user_corrected: true`.

## 8. Risks & mitigations

| Risk | Mitigation |
|------|------------|
| Browser caches a stale `metadata.json` after edit | After successful save, re-render from the response body, not a re-fetch — server already returns the canonical document. |
| User saves while video is mid-frame, no concurrency check | Out of scope; single-user demo. Acknowledge in README. |
| Static mount path collisions on Windows (case-insensitive FS) | Use `Path(...).resolve()` everywhere; never compare paths as strings. |
| Phase 4.4 changes the `Metadata` schema mid-week | Re-run pytest; both halves consume the same `schemas.py`, so a schema change breaks the test loudly. |
| MP4 not in `videos/` because it sits next to the user's source files | README documents the convention; out of scope to support arbitrary paths. |
